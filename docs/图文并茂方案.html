让 AI 日报变成「图文并茂」

基于两篇拆解文章的分析 + 我这边 8 项实测验证 · 2026-10-21

核心结论：这件事不需要 AI 生图，也不需要设计师。橘鸦的封面是程序模板渲染的，正文图是抓来源网站自带的 og:image。整条管线零 API 成本，我今天实测跑通了。

我这边现在是真的 0% 配图：og:image、<img>、enclosure、数据模型里的 images 字段，一个都没有。文章说的问题全部属实。

第二篇《完整拆解与复刻指南》

这篇更有价值，它把橘鸦的机制拆到了工程细节：

封面怎么来的

程序模板渲染：暖色渐变 + 点阵纹理 + 超大日期「10.21」+ 期号 + 头条品牌 logo 圆徽。每个部件都是变量替换，几秒出一张。

正文配图怎么来的

抓来源网页自带的图：og:image、GitHub 社交预览图、官网截图、论文配图、X 推文附图。没有一张是 AI 生成的（它逐张人眼比对过）。

图片目录规律

封面 cover/{YYYYMMDD}/{uuid}.png
正文 imagehub/aidaily/{期UUID}/{源UUID}/m00N_{hash}.png
按「期」和「条」两级归档。

时间节奏

图片 Last-Modified 是发刊前一天下午——流水线在凌晨发布前就把素材备好了。

四、我建议的方案（四步，从便宜到贵）

第 1 步og:image 抓取 —— 一天就能上

收益：约 60-70% 的条目前有图 · 成本 0 · 无需 API Key

每条事件的原始 URL 抓一次 HTML，正则取 og:image，下载存到 data/media/{date}/{event_id}.jpg。失败就留空，不阻塞。

# 我实测可用的降级顺序
1. og:image        （blog.google / theverge / techcrunch 都能取）
2. twitter:image
3. <img> 里最大的一张（排除 icon/logo/1x1）
4. 该域名的 favicon 兜底
拒绝：403 → 换 UA → 仍失败就跳过

需要在 NormalizedItem 加 image_url 字段，在 Event 加 images，渲染时插 <img>。

第 2 步X 推文原图 —— 免费，实测通过

收益：补齐 X 一手内容 · 成本 0

api.fxtwitter.com 免登录、免 Key，返回 media.photos[] 原图直链。只要采集阶段拿到推文 URL，就能取图。

GET https://api.fxtwitter.com/{screen_name}/status/{id}
→ tweet.media.photos[*].url  → https://pbs.twimg.com/media/xxx.jpg?name=orig

下载时带 Referer: https://x.com/ + 浏览器 UA

注意：文章推荐的 vxtwitter 我实测 403，别照抄。

第 3 步封面模板 —— 需要写渲染器

收益：分享卡片从灰变彩 · 成本 0（本地渲染）

不用设计师，也不要用 AI 生图。做法：一个 HTML 模板 + Playwright 截图，变量是「日期 / 期号 / 头条实体 / 背景渐变」。你项目里已经有 Playwright（test_site_interactions.py 在用），直接复用。

cover.html 模板
  ├─ 背景：CSS 线性渐变 + radial-gradient 点阵
  ├─ 中央：日期「10.21」（大号衬线/手写体）
  ├─ 右上：期号「第 054 期」
  └─ 底部：头条品牌圆徽

playwright 截图 → data/media/covers/{YYYYMMDD}.png
→ 同时写进 og:image 和 twitter:card

第 4 步带图 RSS + 分享卡

收益：阅读器里直接看到图 · 改动很小

我已经输出 content:encoded 全文，只要加两行：

<enclosure url="{封面或首图}" type="image/jpeg" length="0"/>
<media:content url="{首图}" medium="image"/>

页面上再加 og:image 与 twitter:card=summary_large_image。

五、我不建议照抄的地方

文章的建议我的判断
技术栈换 Astro / Cloudflare Pages不建议。我现在是 Python + GitHub Pages，为了配图换掉整个渲染层，投入产出比极差。
用 vxtwitter API实测 403，用 fxtwitter。
X API 付费暂时不需要。先做 og:image，X 只取「已经出现在聚合站里的推文链接」，用 fxtwitter 免 Key 取图。
把图放仓库 public/要算清楚：一天 20-60 张图 × 200KB ≈ 4-12MB/天，一年 1.5-4GB。GitHub 仓库会越来越重。建议只存最近 30 天，更早的删文件但保留外链。

六、我建议的执行顺序

顺序做什么为什么是这个顺序
1og:image 抓取 + 渲染 <img>覆盖 60-70% 条目，当天可见效果，零成本
2带图 RSS + og:image meta改动最小（各 2 行），分享卡立刻不灰
3封面模板渲染需要写模板 + Playwright，工作量中等
4X 推文原图依赖第 1 步的下载器，单独加一个取图器即可

七、需要你决定的三件事

  1. 图片存哪？存仓库（简单，但一年 1.5-4GB）／只存 30 天（推荐）／换图床（复杂）。
  2. 封面要不要做？不做也能「图文并茂」（正文有图就够），做了分享出去更专业。
  3. 先做哪个？我建议按上面 1→2→3→4 走，第 1、2 步我一次就能做完。
