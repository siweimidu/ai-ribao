# 前端设计规范

这份文档记录**为什么页面长这样**。每条决策都对应一个可验证的数字或一条明确规则，
而不是「这样比较好看」。改动设计前先读这里，改完跑 `scripts/audit_design.py`。

## 依据

两套外部规范，解压在 `.skills/`（不入库）：

- **Doubao** —— 冷色调极简 AI 仪表盘设计系统。提供令牌：主色 `#0065fd`、
  圆角 `1.2rem`、间距单位 `0.24rem`，以及「边框主导、阴影近乎为零」的层叠方式。
- **motion-web** —— 动效页设计规范。提供弧线选型、实测字阶数据、手感诊断表，
  以及一组必须避开的「AI 味闸门」（design-slop）。

## 一、弧线：`editorial`，不是 `broadside`

规范给出四种弧线。选 `editorial` 的理由是**内容属性**：日报是拿来读的，
读者每天来一次，不是被开场秀吸引的访客。

具体后果：动效预算花在**阅读动作**上（指到哪一行，那一行让位并呼吸），
而不是开场炫技。`broadside` 的「巨字砸下来 + 滚动锁持」在这个场景里是噪音。

规范里有一条失败模式叫「动效在 hero 之后就不重要了」——所有预算花在 hero 上。
这里通过**只给前三行入场**来避免：入场是「你在读这一条」的信号，不是装饰。

## 二、字阶：对比就是设计

规范给的是**实测值**（15 个获奖页，其中 12 个的标题能被 DOM 量到）：

| | 中位数 | 范围 |
|---|---|---|
| 展示字 | **108px** | 52–218px |
| 正文 | **16px** | 10–16px |
| 比值 | **≈8×** | 3.3×–14× |

**下限是 4×**。低于 4× 页面就没有尺度对比，再多留白也救不回来。

更关键的一条观察：**「有几家把正文做到 12px，正是小正文让展示字显得巨大。」**
所以两侧要一起动，只缩一头会把比例改坏。

### 三轮校准的真实过程

| 版本 | 桌面比值 | h1 占高 | 结论 |
|---|---|---|---|
| v1 `clamp(2.5rem,6.5vw,5rem)` / 正文 15px | 5.3× ✅ | **317px** ❌ | 超一屏三分之一 |
| v2 `clamp(2.1rem,5.2vw,3.6rem)` / 正文 15px | **3.8×** ❌ | 147px ✅ | 比例不达标 |
| v3 `clamp(2.4rem,5.4vw,4.75rem)` / **正文 13px** | **5.8×** ✅ | 195px ✅ | 两个约束同时满足 |

v2 的错误是「只缩展示字」——正确做法是把正文一起降下来。

### 中文的特殊性

规范明确点出：**中文展示字在同一光学尺寸下更重，需要更大的行高（1.4–1.6），
负字距会闭合字怀。** 拉丁面惯用的 `line-height: 1.0` / `letter-spacing: -0.04em`
用在中文上会把笔画挤成一团。

所以标题用 **`line-height: 1.28` / `letter-spacing: -0.01em`**。

## 三、移动端是另一种设计，不是缩小版

规范 §7 的原话。实测两轮：

1. `5.4vw` 在 390px 下只有 21px，`clamp` 撞到下限 38px → 比值 3.0×，不合格
2. 改成固定 52px → 比值 4.3× ✅ 但标题换成 **6 行、占满整个首屏**，
   把筛选条和第一条内容全推到屏外

**结论：窄屏真正要守的是「首屏里必须看得到第一条内容」，而不是最大字号。**
最终 40px + `max-width: 100%`（放开桌面的 measure），标题 4 行且首条内容进入首屏。

## 四、配色：4 种

规范实测：**dominant 色中位数是 4 种**，`#ffffff` 出现在 15/15 个页面里。
「两个色相加中性色是配色，一道光谱是演示。」

主色只有一个 `#0065fd`（Doubao 的 primary），加中性灰阶。
**明确禁止紫蓝渐变**（`#6366f1` / `#a855f7` 一类）——那是最可靠的 AI 味标志。
`test_site_design.py` 里有断言。

深色模式用系统 `prefers-color-scheme`，**不做假开关**：不做 localStorage、
不做主题切换按钮。理由是日报没有「用户偏好」这个概念。

## 五、三种段落形态

规范要求一页至少三种不同的段落结构——「每段都是标题 + 居中段落」即使字体完美
也读作模板。

1. **信息带**（masthead）—— 左标题 + 右真实计数的两栏网格
2. **事件流**（stream）—— 序号化的**不等宽**编辑列表：序号 | 内容 | 来源，
   内容列拿走全部余量
3. **归档表**（archive）—— 等宽数字的密集表格

同时避开「默认 hero」（全宽 + 居中大标题 + 副标题 + 两个按钮）和
「居中三列等宽卡片」。

## 六、动效：四个机制，全部原生

不引动效库——规范实测 15 个获奖页里 9 个也没用库。全部 rAF：

| 机制 | 解决什么 | 位置 |
|---|---|---|
| 欠阻尼弹簧 | 「四平八稳/太机械」——普通 lerp 单调减速，读作「滑过去」 | `Spring` 类 |
| 速度耦合 | 「不跟手/没劲」——元素对自身速度作出反应 | `pointermove` 增益 |
| 次级果冻 | 「画面是死的」——环境元素跟随余速晃动 | 序号体积守恒挤压 |
| `1-exp(-k·dt)` | 帧率无关，30/60/120fps 手感一致 | `approach()` |

**刻意不做**（都是闸门点名的）：

- 拖尾圆点光标 —— 2019 年的签名，现在是默认值
- 每个卡片 `translateY(-4px)` + 阴影 —— 对一切生效等于什么都没说
- 全站统一的滚动 fade-up —— 读者到第三段就学会忽略入场
- 单一 `0.3s ease` —— CSS 默认值

`will-change` 只在真正动画时加，`dt` 钳制到 `1/30`（切标签页回来会是几秒）。

## 七、内容绝不依赖动效出现

**这是实际发生过的事故。** 初版把 `.enter { opacity: 0 }` 写在 CSS 里，
观察器没触发时**前三条事件是隐形的**——截图里整段空白，日报看起来是空的。

正确做法：**隐藏由 JS 显式开启**。JS 加上 `js-motion` 类之后才允许隐藏，
所以 JS 挂了内容仍然在。另有「首屏内无条件显示」的兜底，
不把「看得见」这件事交给观察器的时序。

`prefers-reduced-motion` 的分支必须是**同一个页面的完整版本**，不是坏掉的版本。

## 八、真实数字，不用编造的证明

页面上每个数字都是**这次运行数出来的**：事件数、有内容的源数、多源验证数、
采集的源总数、失败数、跳过数、LLM 调用次数与 token 数。

没有「+47% 提升」「50,000+ 团队在用」这类东西。规范把编造证明列为独立闸门（A8）。

数据不全时**显式声明**（`warn` 区块），不留白也不假装完整。

## 九、怎么验证

```bash
# 完整渲染（--no-deliver 不会拷贝资源，产物会是旧的）
python -m aidaily run --from-items data/raw/items.jsonl --no-llm

# 设计闸门：字阶比值、横向溢出、序号与来源列是否塌陷
python scripts/audit_design.py

# 目视：桌面 / 静止帧 / 移动 / 深色 / 索引页
python scripts/shots.py
```

`audit_design.py` 会**先检查产物是否陈旧**，陈旧就以退出码 2 拒绝——
被它坑过两次：改了源、量的是旧副本，报告很漂亮但是错的。

### 一次工具欺骗

`chrome --headless --screenshot` 在字体与布局稳定前就截图，产生了两个看起来像
页面 bug 的假象：「前三条空白」和「序号消失」。DOM 实测显示那些元素都在、
`opacity=1`、位置正常。

**结论是换工具，不是改页面**——改用 Playwright（`scripts/shots.py`），
它等布局和字体稳定。

## 十、CI 断言

`tests/contract/test_site_design.py` 把上述规则变成机器检查：

- 字阶比值 ≥ 4×，且移动端必须**单独**声明字阶
- 中文行高 ≥ 1.2、字距 > -0.03em
- 配色不含紫蓝渐变，accent 只有 2 个值（明/暗）
- 三种段落形态都存在
- `.enter` 不能在 CSS 里自己隐藏
- reduced-motion 分支不隐藏任何内容
- 弹簧帧率无关、有阻尼、`dt` 有钳制
- 只动画 `transform` / `opacity`，不动 layout 属性
- **源资源与产物资源字节一致**
