- 传统 RBAC 模型通常赋予 Admin 查看所有数据的权限，但在此场景下若被举报人拥有 Admin 权限，直接套用 RBAC 会导致被举报人看到针对自己的举报
- 作者建议引入 Content-Aware Authorization 机制，通过代码逻辑判断当前用户是否与举报单存在关联来动态限制访问
- 该机制在工程实施中引发边缘问题，包括如何认定“涉案/关联”范围、调查人员被追加为涉案人后如何实时剥离权限，以及当所有默认有权限者均存在利益冲突时的兜底规则设计
- 作者指出常规 Web 栈默认记录了 IP 等数据，单纯不收集 name 字段不能实现真正的匿名

**推断**
- 若采用传统的静态 RBAC，当被举报人恰好拥有系统最高权限时，现有的权限模型将无法保护举报人的身份安全
- 由于常规 Web 技术栈存在自动记录 IP 等元数据的行为，仅靠删除姓名等明文字段难以在架构层面实现数据最小化

**观点**
