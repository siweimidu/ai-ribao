════════════════════════════════════════════════════════════════════════
二、根因

    git reset --soft FETCH_HEAD

这条命令把**索引**指向远程，但**工作区**保持原样 —— 而这里的工作区只有本次调用
写下的文件。于是远程有、本地没有的文件全部显示为「删除」，接下来的 commit 就把
兄弟文件一起删了。

`store_images` 一期跑两次（文章配图、仓库卡片），所以第一次删第二次的，
第二次删第一次的，最后剩下一堆空提交。

════════════════════════════════════════════════════════════════════════
三、修法

    git checkout -f FETCH_HEAD -- .

`reset --soft` 只是移动索引，`checkout` 会**把远程的文件真正取到磁盘上**。
本地文件保住，远程文件到位，`git add -A` 提交的是并集而不是替换。

实测对比：

  旧（reset --soft）: 新增 15，删除 4
  新（checkout）    : 新增 19，删除 0
