fix(media): 配图 38 张全被拒 —— checkout 之后 HEAD 没跟上

════════════════════════════════════════════════════════════════════════
一、诊断行直接指出了断点

上一轮加的三行输出，这次立刻定位：

  配图上传：磁盘 38 个文件，git 待提交 42 项    ← 文件写好了
  配图上传：推送失败 rc=1                       ← 推送被拒
    ! [rejected] HEAD -> main (non-fast-forward)

配图数量从 0 涨到 **38 张**（images_max 那次修复生效），但一张都没推上去。

════════════════════════════════════════════════════════════════════════
二、根因

`git checkout -f FETCH_HEAD -- .` 把远程文件取到磁盘，**但 HEAD 还停在本地旧提交**。
于是新 commit 不是远程 tip 的后代，push 被判 non-fast-forward。

两个命令各缺一半：

  checkout  →  文件到位，HEAD 不动   →  非快进，被拒
  reset --soft  →  HEAD 到位，文件不动  →  兄弟文件显示为删除

上一版我只用了 checkout，把第二个 bug 换成了第一个。

════════════════════════════════════════════════════════════════════════
三、修法：两个都要

  git checkout -f FETCH_HEAD -- .   ← 文件到位（并集，不删兄弟）
  git reset --soft FETCH_HEAD       ← HEAD 跟到远程 tip

顺序不能反：先 reset 再 checkout，工作区还是旧的。

实测：

  HEAD == FETCH_HEAD: True
  待提交: 3 项，新增 3，删除 0

推送失败的 retry 分支也补了同样两步。
