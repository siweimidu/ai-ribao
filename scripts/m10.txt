fix(github): 标题要说清是什么，老仓库不该当新闻

════════════════════════════════════════════════════════════════════════
一、你指出的两件事

1. 标题只有 `anthropics/knowledge-work-plugins`，没说清是什么
2. 这仓库是 2026-01-23 创建的，**9 个月前**，不是今天的新消息

════════════════════════════════════════════════════════════════════════
二、核实

GitHub API：

  created: 2026-01-23T20:11:54Z    ← 9 个月前
  pushed : 2026-10-23T07:38:30Z    ← 今天有提交
  stars  : 32066

它上 Trending 是因为**今天有推送**，不是今天开源。

`github_trending.py` 的注释其实早就写明了这一点：

  「Trending 是星标增量窗口，不是发布事件：2019 年创建的仓库也可以因为今天涨星上榜。
    附上抓取时间会让日报宣称这个项目『今天发布』。」

**但代码只做对了一半：`published_at=None` 是对的，可排名时把它当成「未知新鲜度」
给了中性值 0.5，等于默认它不旧。**

════════════════════════════════════════════════════════════════════════
三、标题

原来是 `title=full_name`。description 已经抓到了、已经进了 summary，
**只是没进读者第一眼看的那个字段。**

改成：

  anthropics/knowledge-work-plugins — Open source repository of plugins primarily…

用破折号不用冒号，因为仓库描述本身常含冒号，一行两个冒号读起来像出错。
超过 90 字按词边界截断。

════════════════════════════════════════════════════════════════════════
四、仓库年龄

`heat.py` 的 `_freshness` 对所有无日期条目返回 0.5。现在乘以仓库年龄系数：

  ≤ 14 天   1.00   真正的新项目
  ≤ 60 天   0.75   近期
  ≤ 365 天  0.45   老项目今天有事
  > 365 天  0.20   老项目又被翻出来

年龄来自 GitHub API 的 `created_at`，在 `build_events` 之后、评分之前写入
`item.metrics["repo_created"]`。一期只有几个仓库，几次 API 调用。

**取不到年龄就保持中性值** —— 猜会静默埋掉真正的新项目。
