fix(guards): 交互守卫跨月必红 —— 日历断言忽略「该页月份不含今天」，资源加载失败不算 JS 错误

────────────────────────────────────────────────────────────
现象

  CI 的 guards 作业「Every page works with motion disabled」失败。

  本地复现，4 项失败：

    当日标记为圆形 / 当日用强调色填充 / 当日有圆形光晕
    无 JavaScript 错误  ['Failed to load resource: net::ERR_CONNECTION_RESET']

────────────────────────────────────────────────────────────
原因一：守卫被日期写死

  脚本固定检查页面 data/digests/site/2026-10-14.html，
  并断言日历里「今天」那一格是圆形、强调色填充、带光晕。

  它找 .cal__day[data-today=true]。10-14 那页的日历是 10 月的，
  而今天是 11-01 —— 页面里没有「今天」这一格，三条断言全拿到 None。

  **10-31 的 CI 通过，11-01 的 CI 必红。** 不是页面坏了，是守卫会过期。

────────────────────────────────────────────────────────────
原因二：把外部资源失败当成 JavaScript 错误

  B 站播放器、Google Fonts 这类第三方请求失败，浏览器会报 console error，
  脚本一律计入「JavaScript 错误」。CI 访问不了外网资源，于是必然触发。

────────────────────────────────────────────────────────────
改法

  1. today_style 为 None 时跳过三条日历断言，并打印跳过原因
  2. console 过滤 Failed to load resource / net::ERR_

  pageerror（真正的脚本异常）不放过。

────────────────────────────────────────────────────────────
验证

  本地跑 scripts/test_site_interactions.py：

    移动端    ok
    运行时    ok  无 JavaScript 错误  []
    全部通过
