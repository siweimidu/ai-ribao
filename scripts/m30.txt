fix(analyze): 术语被拆字硬译 —— Open Weights 变成「公开组重量」

════════════════════════════════════════════════════════════════════════
一、你看到的那句

  原文  Fable-5.1-Class Open Weights narrows Closed-Weighted gap
  改写  Fable-5.1-公开组重量差距缩小，AI领先优势缩至1个月

**`Open Weights` 被逐词拆成了「公开组重量」** ——
open 读成公开，weights 读成重量。读者会以为这句话在讲物理重量。

同样的坑：`Context Window` → 上下文窗户、`Benchmark` → 长凳标记、
`Zero-shot` → 零射击。

════════════════════════════════════════════════════════════════════════
二、根因

提示词只说了「专有名词保留原文」，举的例子都是**单词**
（OpenAI、Gemini、GPT-6），没有覆盖**多词固定搭配**。
模型看到 `Open Weights` 两个词，就当普通短语翻译了。

════════════════════════════════════════════════════════════════════════
三、两层防护

**第一层：改提示词**

新增「术语怎么处理」一节，明确列出：

  Open Weights / Context Window / Fine-tuning / Zero-shot / Benchmark / MoE / RLHF
  以及一句硬规则：**不确定的英文术语，保留原文，比硬译更准**

「译错的代价比不译大：读者看到『公开组重量』会以为说的是物理重量。」

**第二层：输出校验**

`title_is_safe()` —— 提示词是请求，不是保证。检测到拆字痕迹就退回英文原标题：

  _MISTRANSLATED_TERMS = 公开组重量 / 开放组重量 / 封闭重量 /
                         上下文窗户 / 长凳标记 / 微量调 / 零射击

`_safe_title()` 用它决定标题：**宁可发英文，不发一句自信但错误的中文。**
