fix(ci): 模型榜一天只刷新一次 —— 独立成 job，不再受发布闸门限制

════════════════════════════════════════════════════════════════════════
一、你问「是不是每天整理日报时一起做」

**原来是的，而且这是个缺陷。**

链路是：`publish` job → `write_site()` → 生成 leaderboard.html。

但 `publish` 有 `if: needs.gate.outputs.run == 'true'` —— 闸门的作用是让一天只发布一次。

所以一天三个时段里：

  04:00  闸门说「要发」→ 构建日报 → 顺带刷新模型榜 ✓
  12:00  闸门说「已发过」→ 整个 publish 跳过 → 模型榜不动
  20:00  同上 → 模型榜不动

**结果：模型榜显示的是天亮前的数据，一直挂到第二天。**

════════════════════════════════════════════════════════════════════════
二、为什么不该跟着日报走

日报是「今天的事件」，一天一次是对的。

模型榜是**外部服务的数据**，它跟着 artificialanalysis.ai 更新，不跟着我们的发布账本。
两个节奏不同的东西绑在一起，慢的那个会被快的拖住。

════════════════════════════════════════════════════════════════════════
三、改成独立 job

新增 `leaderboard` job：

  needs: [gate]
  if: always() && needs.gate.result != 'failure'

它不依赖 publish 的结果，闸门跳过时照常运行。

新增命令：

  python -m aidaily leaderboard --max-age-hours 6

只读快照、只重写一个文件，不采集、不分析、不投递。快照够新时打印
「页面已是最新」并退出 0 —— 每时段 6 次冗余 cron 不会反复搅动仓库。

`deploy` 的依赖同步改成 `[publish, leaderboard]`，否则模型榜的提交来不及进
部署产物。

════════════════════════════════════════════════════════════════════════
四、顺带调整

  快照 TTL 12h → 6h

12 小时意味着 12:00 那次会复用 04:00 的数据。6 小时保证每个时段看到的都是本时段的。

════════════════════════════════════════════════════════════════════════
五、验证

  python -m aidaily leaderboard --max-age-hours 0
  → 已刷新 leaderboard.html（272 个模型）  exit 0

  actionlint 通过；job 图：

    leaderboard needs=gate        ← 不受 publish 影响
    deploy      needs=[publish, leaderboard]
