一、你看到的标题是怎么来的

  anthropics/knowledge-work-plugins：Claude Cowork 知识工作插件

**这不是我写的格式，是 LLM 改写的。**

`_display_title` 优先用 insight.title（模型生成的中文标题），而模型对仓库条目做的
就是「仓库名 + 全角冒号 + 描述的中文翻译」——读起来像坏掉的标签，不是标题，
而且和下面卡片里已经显示的描述重复。

════════════════════════════════════════════════════════════════════════
二、更严重的问题：它在「待翻译」折叠区里

查页面时发现这条根本不在正文，而是被塞进了「本期待翻译条目（2 条）」。

原因：`_looks_chinese(title)` 判定英文就归入待翻译块。

**但仓库名本来就没有中文形式，永远不会有。** 把它当作「没能翻译的外文报道」，
等于告诉读者「这条我们处理不了」，而实际上这条是完整的。

════════════════════════════════════════════════════════════════════════
三、三处修改

**1. 仓库条目保留自己的标题**

  标题 = anthropics/knowledge-work-plugins
  描述留在 summary（本来就在）

**2. 仓库条目不进待翻译区**

  条件是 `_is_repository_story(event)`，用 URL 判定，不看语言。

**3. 时间标签说人话**

  原来一律「时间未知」，现在有创建日期时显示：

    Trending，9 个月前创建
    Trending，3 天前创建
    Trending，2 年前创建

取不到才显示「时间未知」——猜一个年龄比不显示更糟，读者靠它判断是不是新闻。

════════════════════════════════════════════════════════════════════════
四、仓库识别的边界

`github.com/topics/llm`、`/features/actions`、`/trending` 这些**不是仓库**，
两段路径长得一样但语义不同。排除了 23 个 GitHub 保留路径。

误判的后果是：一条只是链接到 GitHub 的新闻会失去中文标题改写。
