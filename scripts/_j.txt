fix(collect): 一行截断的 JSON 让整期日报发不出来

一、今天 action 为什么没成功

先说结论：**schedule 是触发的，失败在 publish**。

  00:42:58 UTC  schedule           success
  00:43:07 UTC  workflow_dispatch  failure  ← 9 秒后手动触发

昨晚那次（北京 06:52）的完整过程：

  ✓ gate      17s
  ✓ collect   24m19s
  X publish   3m25s  ← 失败
      publish attempt 1 / 3  failed
      publish attempt 2 / 3  failed
      publish attempt 3 / 3  failed

════════════════════════════════════════════════════════════════════════
二、publish 失败的真正原因

  pydantic_core.ValidationError: 1 validation error for NormalizedItem
  Invalid JSON: EOF while parsing a string at line 1 column 2067

`data/raw/items.jsonl` 里有一行**写了一半**。collect 阶段写文件时被中断，
留下半条记录。

而 `read_items_jsonl` 是这样的：

    for line in p.read_text().splitlines():
        if line:
            out.append(NormalizedItem.model_validate_json(line))   # ← 一行坏，全崩

**几千条记录里坏了一条，整期日报发不出来。** 重试三次，三次崩在同一行。

════════════════════════════════════════════════════════════════════════
三、修法

跳过错行，并报告跳了多少：

    try:
        out.append(NormalizedItem.model_validate_json(line))
    except Exception:
        skipped += 1
    if skipped:
        print(f"items.jsonl: skipped {skipped} unparseable line(s)", file=sys.stderr)

被中断的作业留下半截文件是常态，不是需要往上抛的异常。

四、顺带修的第二个问题

collect 用了 **24 分钟**，但采集本身只花了 24 秒 —— 其余时间在等 4 个关键源
（juya、hex2077、dailydawn、ainewslog）发布当日版。等了 20 分钟，它们没发。

  --wait-critical 20  →  8
  AIDAILY_RUN__CRITICAL_WAIT_MINUTES 20 → 8

等 20 分钟换来的是空手，这 20 分钟没有价值。
