fix(entities): 中文实体按虚词切分 —— 一次大会被拆成六个事件

════════════════════════════════════════════════════════════════════════
一、现象

2026-10-21 那期里，同一场「2026物理AI与世界模型大会」的 7 篇报道
变成了 7 个独立事件，各自参与排序，谁也没能代表这件事。

════════════════════════════════════════════════════════════════════════
二、查证过程（每一步都有实测）

1. 聚类本身是对的 —— 把 109 个事件重新跑 coarse_clusters，7 条聚成 1 个簇
2. merge_unambiguous 判定也是 True —— shared=3, best_sim=0.667
3. 但 shared_entities 是 ['模型', '生成'] —— **全是泛化词**

第 3 步是根因。实体提取把「物理AI与世界模型大会」按固定宽度切成：

   与世 / 界模 / 型大 / 域分 / 多领 / 器全 / 球首 ...

六篇报道共享的只是这些碎片，`merge_unambiguous` 拿这种实体去判断，
自然判不准 —— 它看到的是「都提到模型和生成」，而不是「都在讲同一场大会」。

════════════════════════════════════════════════════════════════════════
三、修法

按**虚词边界**切分，而不是按固定宽度：

   与 和 及 的 在 为 对 从 到 把 被 让 使 以 于 而 或 但 也 都 还 就 又 ...

切出来的就是名词短语。同一个标题现在提取到：

   ['世界模型大会', '南京广播电视台', '物理', '多领域分会场活动', ...]

前两篇共享 3 个实体（世界模型大会 / 南京广播电视台 / 物理），能正确聚类。

仍保留降级：整段没有虚词时退回二字切片，不丢词。

════════════════════════════════════════════════════════════════════════
四、验证

  同一大会的两篇    共享 3 个实体  ✓
  大会 vs 黄仁勋演讲  共享 1 个实体  ✓ 不该合并的没被合并

五、5 项新测试

名词短语完整保留、同一大会的报道共享实体、无关故事共享很少、
单字碎片被丢弃、无虚词时仍产出结果。
