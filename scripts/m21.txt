fix: 发布流程崩溃 —— 直通名单与不可违反的断言互相矛盾

════════════════════════════════════════════════════════════════════════
一、这次失败的原因

AI Daily 运行 40069640955 连试三次都失败：

  AssertionError: select_diverse reintroduced stories below the AI relevance floor:
  日本数字厅 AI 建站翻车…; Google Pro 用户反馈 Antigravity…

**是我上一轮加直通名单造成的。**

  · 筛选阶段：直通源跳过相关性门槛，低分条目被保留
  · 发布边界：一条断言要求「每条都必须过门槛」，不知道直通名单存在

两条规则单独看都对，放在一起必然冲突。

════════════════════════════════════════════════════════════════════════
二、修法

让断言问和筛选同一个问题：

  violating = [row.event.title for row in chosen
               if not passes_ai_relevance(focus)
               and not is_passthrough(row.event)]

════════════════════════════════════════════════════════════════════════
三、同时发现自检一直没运行

我加合并自检时写了：

  Digest(date=today, top_events=[...])

`Digest` 有 5 个必填字段，漏了 `kind`、`generated_at`、`window_start`、`window_end`。

**报错被 except 吞掉，日志写「未运行」，我上一轮没注意到。**

改成 `inspect(events, headlines)` —— 它只读 `event_id`/`title`/`member_item_ids`，
不需要完整的 Digest。少一层间接，就少一个能漏字段的地方。

════════════════════════════════════════════════════════════════════════
四、这次我真的跑了端到端

之前几次都只跑单元测试就提交，所以流水线级别的错误漏过去了。

  python -m aidaily run --no-llm --no-deliver

  events     : 89  （之前 36）
  合并自检   : 可疑 2 条  ← 真的在跑了
  exit       : 0

════════════════════════════════════════════════════════════════════════
五、5 项新测试

断言必须豁免直通源（直接读源码验证）、低分直通条目两条规则都放行、
低分普通条目两条都拦、直通名单里的 id 格式合法、置顶规则与门槛不冲突。

════════════════════════════════════════════════════════════════════════
六、以后不再重犯

改动涉及发布流程时，**必须跑一次 `python -m aidaily run --no-llm --no-deliver`**，
不能只跑 pytest。这次的问题 pytest 全绿也发现不了，它只在真实流水线里出现。
