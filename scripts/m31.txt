一、为什么要独立成文件

去重规则是**这个项目里最重要的一段文字**：

  该合并没合并  →  同一件事刷屏三遍
  不该合并合并了 →  **凭空制造「多家媒体证实」的假象**

这段判断每次运行都要重做一遍，而且每踩一次坑就该长一条规则
（三条 Kimi、汇总稿陷阱、发布 vs 评测…）。

写在 Python 里是一串转义拼接，改一次要数引号；写成 Markdown 才能当文档审阅。

二、`config/dedup_prompt.md`（135 行）

结构：

  一、必须合并的 5 种情况，每种带真实正例
      同一模型发布 / 同一笔融资 / 同一起事故 / 同一份报告 / 同一场演讲

  二、绝对不能合并的 5 种情况，每种带反例
      同公司不同产品 / 发布vs评测 / 两家公司同类产品 / 同产品不同时间 / 汇总稿

  三、判断顺序（主体 → 动作 → 时间 → 是否汇总稿）
  四、拿不准的时候：不合并
  五、输出格式与硬性要求

核心正例就是这次踩的坑：

  ✅ Moonshot AI 推出 3 万亿参数 Kimi K3.1 Pro
  ✅ 全球最大 3 万亿参数开源AI模型上线

「第三条通篇没有 Kimi 三个字，它说的是同一件事 ——
 中文媒体常把产品名换成一串定语。」

并且写明了两种错的代价不对等：

「误合并会凭空制造『多家媒体证实』的假象，读者据此相信一条可能不实的消息。
  漏合并只是重复一次，读者能自己看出来。」

════════════════════════════════════════════════════════════════════════
三、加载方式

  PROMPT_PATH = config/dedup_prompt.md
  SYSTEM = load_prompt()

**文件缺失或为空时回退到内置三条核心规则** —— 打包出错不能让去重静默失效。
