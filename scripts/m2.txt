fix(llm): 推理模型的 max_tokens 下限 —— 256 必然返回空内容

一、你问「我是怎么解决的」

上一轮我**只是把问题记了下来，没有解决**。这次真的修了。

════════════════════════════════════════════════════════════════════════
二、查到的实际情况

代码里三处 max_tokens：

  l3.py:201      256     ← 对推理模型必然返回空
  analyze.py:198 900
  rubric.py:310  4000

`client.py` 已经会把空内容转成错误（ProviderError），让路由换下一个供应商。
所以不会崩，但每次 L3 判定都要**先浪费一次调用**才知道这个模型不能这么用。

════════════════════════════════════════════════════════════════════════
三、修法：让 spec 自己声明

`ProviderSpec` 新增两个字段：

  reasoning: bool = False        这个模型会不会先思考再回答
  reasoning_floor: int = 1024    如果是，max_tokens 至少给这么多

请求构造时：

  effective = max_tokens
  if spec.reasoning:
      effective = max(max_tokens, spec.reasoning_floor)
  payload["max_tokens"] = effective

`is_reasoning_model()` 按模型名片段识别，因为各家写法带前后缀：

  gpt-oss / deepseek-r / -r1 / qwq / thinking / reasoning / o1- / o3-

四、验证

  10 个模型名识别全部正确：
    openai/gpt-oss-120b  → True
    openai/gpt-oss-20b   → True
    deepseek-r1          → True
    qwq-32b              → True
    agnes-3.0-flash      → False

  预算换算：
    推理模型 max_tokens=256  → 1024（抬到下限）
    推理模型 max_tokens=4000 → 4000（不下调）
    普通模型 max_tokens=256  → 256 （不变）
