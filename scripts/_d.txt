fix(media): 配图文件从未进过提交 —— 加诊断定位

════════════════════════════════════════════════════════════════════════
一、现象

今天那期页面里所有配图都是破图，缩略图位置显示成一个空框（被误认为多余按钮）。

证据链：

  归档 image_urls     15 条，URL 指向 2026-10-22/xxx.webp
  媒体仓库 2026-10-22  目录不存在
  媒体仓库全部文件     4 个，全是 2026-10-21
  git log             10 次 media: 2026-10-22 提交
  这些提交的内容      只有 2026-10-21 的旧文件，0 个 10-22 文件

所以：提交推上去了，配图从没进去。

════════════════════════════════════════════════════════════════════════
二、复现到的关键事实

在全新目录里按 _push 的步骤走一遍（init → fetch --depth 1 → reset --soft
→ add -A），git status 给出：

  D  2026-10-21/e583c9b47b195dd-1e4e59ea.webp     ← 旧文件被标记删除
  D  2026-10-21/e70ade8fddebdc9-678602b0.webp
  A  2026-10-22/e-test-00.webp                     ← 新文件
  A  2026-10-22/e-test-01.webp

`reset --soft FETCH_HEAD` 把索引指向远程，而工作区只有本地写下的文件，
于是远程有、本地没有的文件全部显示为删除。这个副作用本身不致命，但它说明
这条路径的中间状态比预期复杂得多。

════════════════════════════════════════════════════════════════════════
三、这一版做了什么

没有猜着改。加了三行诊断，让下一次运行直接说出是哪一环断的：

  磁盘 N 个文件，git 待提交 M 项
  没有可提交的内容（磁盘 N 个文件但 git 无差异）
  git add 失败 rc=X

以前这三种情况都是静默的 —— store_images 返回 urls，页面拿着 URL 显示破图，
没有任何一行日志能区分「文件没写」「写了被 git 忽略」「写了但推送失败」。

顺带删掉了本地 data/media-repo 残留：CI 每次都是全新 checkout，本地这份
只有 10-21 的旧文件，却让排查时误以为推送发生了。它已在 .gitignore 里。
