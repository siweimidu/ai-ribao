一、你截图里的第 02 条为什么还在

  01  Moonshot AI 推出 3 万亿参数 Kim K3.1 Pro
  02  Kimi 3.1 Pro 推出 Fable-5.1 开放权重与高速 API   ← 同一件事，没合并

**我的 scale 分桶把这条漏了：它不提参数量。**

  Moonshot AI 推出 3 万亿参数 Kim K3.1 Pro      → scale:3T
  Kimi 3.1 Pro 推出 Fable-5.1 开放权重与高速 API  → (无 scale)

一个键分不开「该在一起的」—— 这是**分区**的思路，而实际需要的是**连通**。

════════════════════════════════════════════════════════════════════════
二、三次尝试

  第 1 版  固定切片 40 条 → Kimi 散在 1/3/1 三批
  第 2 版  按实体分桶     → 实体各不同，仍散
  第 3 版  scale 优先     → 漏掉没写参数量的那条

**共同错误：假设「同一件事」可以用一个键表达。**

实际上：

  A 和 B 共用一个实体
  B 和 C 共用一个参数规模
  A 和 C 什么也不共用

但它们是一件事。这是**图的连通分量**问题，不是分区问题。

════════════════════════════════════════════════════════════════════════
三、并查集

  特征 = 每个识别出的实体 + 参数规模
  两条事件共用任一特征 → union
  桶 = 连通分量

**故意过度分组**：一批里混进两条无关新闻没有代价，因为模型会自己判断要不要合并。
反过来，一批里藏住了一条本该合并的，就是我连续犯四次的错。
